# DAX in Power BI — Complete Tutor Notes
### For a Beginner Moving Toward Industry-Level Skill

---

## 1. What is DAX?

**DAX (Data Analysis Expressions)** is the formula language used in Power BI, Excel Power Pivot, and SSAS Tabular to create **Calculated Columns, Measures, and Calculated Tables**.

Think of DAX as Excel formulas that understand **relationships between tables** and **filter context**, not just single cells.

### Where DAX is used
| Object | Purpose | Stored | Recalculated |
|---|---|---|---|
| **Calculated Column** | Row-by-row value, becomes part of the table | On disk (uses RAM/storage) | Only on data refresh |
| **Measure** | Aggregated value, calculated on the fly | Not stored | Every time a visual/filter changes |
| **Calculated Table** | A new table generated by a DAX expression | On disk | On data refresh |

**Industry rule of thumb:** Prefer **Measures** over Calculated Columns wherever possible — they're lighter on the model and respond dynamically to filters/slicers.

---

## 2. DAX Syntax Basics

### 2.1 General structure
```DAX
MeasureName = FUNCTION ( Argument1, Argument2, ... )
```

Example:
```DAX
Total Sales = SUM ( Sales[SalesAmount] )
```

### 2.2 Table and column referencing
```DAX
TableName[ColumnName]     -- fully qualified column reference (always use this)
[MeasureName]              -- measures are referenced without a table name
```

### 2.3 Operators

| Type | Operators | Example |
|---|---|---|
| Arithmetic | `+ - * / ^` | `Price * Qty` |
| Comparison | `= > < >= <= <>` | `Sales[Qty] > 0` |
| Text concatenation | `&` | `[FirstName] & " " & [LastName]` |
| Logical | `&&` (AND), `\|\|` (OR), `NOT` | `Sales[Qty] > 0 && Sales[Price] > 0` |

### 2.4 Comments
```DAX
// single line comment
/* multi
   line comment */
```

## 3. The Most Important Concept: Context

This is what separates DAX from Excel — **master this before memorizing functions.**

### 3.1 Row Context
Exists in **calculated columns** and inside **iterator functions** (those ending in `X`, like SUMX). DAX evaluates the formula **row by row**.

```DAX
-- Calculated Column
Profit = Sales[SalesAmount] - Sales[CostAmount]
```
Here, each row automatically knows its own `SalesAmount` and `CostAmount`.

### 3.2 Filter Context
Exists in **measures**. It's the set of filters applied by slicers, rows/columns in a visual, or other DAX functions (like CALCULATE).

```DAX
Total Sales = SUM ( Sales[SalesAmount] )
```
If this measure sits in a matrix visual with "Region" on rows, Power BI automatically applies a filter context of one region at a time — you don't write that filter, the visual does.

### 3.3 Context Transition
When a row context needs to be converted into a filter context — this happens automatically inside `CALCULATE` or any iterator (`SUMX`, `FILTER`, etc.).

```DAX
Sales Value = SUMX ( Sales, Sales[Qty] * Sales[UnitPrice] )
```
Here `SUMX` moves row-by-row through `Sales`, and for each row it evaluates `Qty * UnitPrice`, then sums the results.

## 4. Function Categories with Syntax & Examples

## 4.1 Aggregation Functions

| Function | Syntax | Description |
|---|---|---|
| SUM | `SUM(Column)` | Adds up a numeric column |
| AVERAGE | `AVERAGE(Column)` | Arithmetic mean |
| MIN / MAX | `MIN(Column)` / `MAX(Column)` | Smallest/largest value |
| COUNT | `COUNT(Column)` | Counts numeric/date cells |
| COUNTA | `COUNTA(Column)` | Counts non-blank cells (any type) |
| COUNTROWS | `COUNTROWS(Table)` | Counts rows in a table |
| DISTINCTCOUNT | `DISTINCTCOUNT(Column)` | Counts unique values |

**Industry example (Retail):**
```DAX
Total Revenue = SUM ( Sales[SalesAmount] )

Number of Orders = DISTINCTCOUNT ( Sales[OrderID] )

Avg Order Value = DIVIDE ( [Total Revenue], [Number of Orders] )
```

> **DIVIDE()** is the industry-standard safe division function — it avoids divide-by-zero errors:
> `DIVIDE ( Numerator, Denominator, [AlternateResult] )`

---

## 4.2 Iterator (X) Functions

These loop **row by row** over a table, then aggregate the result.

| Function | Syntax |
|---|---|
| SUMX | `SUMX(Table, Expression)` |
| AVERAGEX | `AVERAGEX(Table, Expression)` |
| MAXX / MINX | `MAXX(Table, Expression)` |
| COUNTX | `COUNTX(Table, Expression)` |
| RANKX | `RANKX(Table, Expression, [Value], [Order], [Ties])` |

**Industry example (Finance — margin calc where Price and Cost are in different columns per row):**
```DAX
Total Profit = SUMX ( Sales, Sales[Qty] * (Sales[UnitPrice] - Sales[UnitCost]) )
```

**Industry example (Sales — ranking products by revenue):**
```DAX
Product Rank = RANKX ( ALL ( Product[ProductName] ), [Total Revenue], , DESC )
```
This ranks products independent of any slicer filter on ProductName, using DESC (highest revenue = rank 1).

---

## 4.3 Logical Functions

| Function | Syntax |
|---|---|
| IF | `IF(LogicalTest, ResultIfTrue, ResultIfFalse)` |
| SWITCH | `SWITCH(Expression, Value1, Result1, ..., ElseResult)` |
| AND / OR / NOT | `AND(Expr1, Expr2)` |
| IFERROR | `IFERROR(Value, ValueIfError)` |

**Industry example (Sales performance tagging):**
```DAX
Performance Tag =
SWITCH (
    TRUE(),
    [Total Revenue] >= 1000000, "Excellent",
    [Total Revenue] >= 500000, "Good",
    [Total Revenue] >= 100000, "Average",
    "Needs Improvement"
)
```
`SWITCH(TRUE(), ...)` is a very common industry pattern replacing long nested IFs — it's cleaner and easier to maintain.

## 4.4 Filter Functions — The Heart of DAX

### CALCULATE — the most important function in DAX
```DAX
CALCULATE ( Expression, Filter1, Filter2, ... )
```
It evaluates an expression in a **modified filter context**.

**Industry example (comparing to a fixed category):**
```DAX
Online Sales = CALCULATE ( [Total Revenue], Sales[Channel] = "Online" )
```

### Other filter functions

| Function | Syntax | Use |
|---|---|---|
| FILTER | `FILTER(Table, Condition)` | Returns a filtered table, usually nested inside CALCULATE |
| ALL | `ALL(Table or Column)` | Removes filters |
| ALLEXCEPT | `ALLEXCEPT(Table, Column1, ...)` | Removes all filters except listed columns |
| ALLSELECTED | `ALLSELECTED(Table or Column)` | Keeps filters from outside the visual, removes filters from inside it |
| REMOVEFILTERS | `REMOVEFILTERS(Table or Column)` | Explicitly clears filters (modern replacement for ALL in this role) |
| KEEPFILTERS | `KEEPFILTERS(Filter)` | Adds instead of replacing existing filters inside CALCULATE |

**Industry example (% of Total — a classic retail dashboard KPI):**
```DAX
% of Total Sales =
DIVIDE (
    [Total Revenue],
    CALCULATE ( [Total Revenue], ALL ( Sales ) )
)
```
This shows each region/category's share of total sales, regardless of which slice is currently filtered.

**Industry example (High value orders only):**
```DAX
High Value Sales =
CALCULATE (
    [Total Revenue],
    FILTER ( Sales, Sales[SalesAmount] > 10000 )
)
```

## 4.5 Text Functions

| Function | Syntax |
|---|---|
| CONCATENATE | `CONCATENATE(Text1, Text2)` |
| LEFT / RIGHT | `LEFT(Text, NumChars)` |
| MID | `MID(Text, StartPos, NumChars)` |

**Industry example (building a customer full-name and a formatted KPI label):**
```DAX

```

## 4.6 Date & Time Functions

| Function | Syntax |
|---|---|
| TODAY / NOW | `TODAY()` |
| YEAR / MONTH / DAY | `YEAR(Date)` |
| DATE | `DATE(Year, Month, Day)` |
| DATEDIFF | `DATEDIFF(Date1, Date2, Interval)` |
| EOMONTH | `EOMONTH(StartDate, Months)` |
| WEEKDAY | `WEEKDAY(Date, ReturnType)` |
| DATEVALUE | `DATEVALUE(Text)` |

**Industry example (customer tenure / aging analysis):**
```DAX
Days Since Last Purchase = DATEDIFF ( [LastPurchaseDate], TODAY(), DAY )

Customer Status =
IF ( [Days Since Last Purchase] > 180, "Churn Risk", "Active" )
```

## 4.7 Time Intelligence Functions

> These require a proper **Date table** marked as a Date Table in the model, related to the fact table.

| Function | Syntax | Meaning |
|---|---|---|
| TOTALYTD | `TOTALYTD(Expression, Dates, [Filter], [YearEndDate])` | Year-to-date |
| TOTALQTD / TOTALMTD | Same pattern | Quarter/Month to date |
| SAMEPERIODLASTYEAR | `SAMEPERIODLASTYEAR(Dates)` | Shifts filter context back one year |
| DATEADD | `DATEADD(Dates, NumberOfIntervals, Interval)` | Shifts dates by any interval |
| PARALLELPERIOD | `PARALLELPERIOD(Dates, NumberOfIntervals, Interval)` | Similar to DATEADD but returns full periods |
| PREVIOUSMONTH / PREVIOUSYEAR | `PREVIOUSMONTH(Dates)` | Previous period as a table |
| DATESYTD / DATESQTD / DATESMTD | `DATESYTD(Dates, [YearEndDate])` | Returns a date table used inside CALCULATE |

**Industry example (Finance — YoY Growth, the single most requested Power BI KPI):**
```DAX
Sales YTD = TOTALYTD ( [Total Revenue], 'Date'[Date] )

Sales PY = CALCULATE ( [Total Revenue], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )

YoY Growth % = DIVIDE ( [Total Revenue] - [Sales PY], [Sales PY] )
```

**Industry example (rolling 3-month average — common in demand forecasting):**
```DAX
Rolling 3M Avg Sales =
AVERAGEX (
    DATESINPERIOD ( 'Date'[Date], MAX ( 'Date'[Date] ), -3, MONTH ),
    [Total Revenue]
)
```

## 4.8 Relationship Functions

| Function | Syntax | Use |
|---|---|---|
| RELATED | `RELATED(Column)` | Pulls a column from the "one" side table into the "many" side (row context) |
| RELATEDTABLE | `RELATEDTABLE(Table)` | Pulls related rows from the "many" side into the "one" side |
| USERELATIONSHIP | `USERELATIONSHIP(Column1, Column2)` | Activates an inactive relationship for one calculation |

**Industry example (calculated column pulling category into Sales table):**
```DAX
Category = RELATED ( Product[Category] )
```

**Industry example (using a second date relationship, e.g. Ship Date vs Order Date):**
```DAX
Shipped Revenue =
CALCULATE (
    [Total Revenue],
    USERELATIONSHIP ( Sales[ShipDate], 'Date'[Date] )
)
```

## 4.9 Table Manipulation Functions

| Function | Syntax | Use |
|---|---|---|
| SUMMARIZE | `SUMMARIZE(Table, GroupByCol, "Name", Expr)` | Group-by table with aggregations |
| ADDCOLUMNS | `ADDCOLUMNS(Table, "Name", Expr)` | Adds calculated columns to a table expression |
| SELECTCOLUMNS | `SELECTCOLUMNS(Table, "Name", Expr)` | Projects specific columns |
| UNION | `UNION(Table1, Table2)` | Stacks tables with matching columns |
| CROSSJOIN | `CROSSJOIN(Table1, Table2)` | Cartesian product of two tables |
| GENERATE | `GENERATE(Table1, Table2)` | Row-context cross join (like a correlated subquery) |
| TOPN | `TOPN(N, Table, OrderByExpr, Order)` | Returns top N rows |
| VALUES | `VALUES(Column)` | Distinct values in current filter context |
| DISTINCT | `DISTINCT(Column or Table)` | Distinct values/rows |

**Industry example (Top 5 customers by revenue — used in calculated tables or measures):**
```DAX
Top5 Customers =
TOPN (
    5,
    SUMMARIZE ( Sales, Customer[CustomerName], "Rev", [Total Revenue] ),
    [Rev], DESC
)
```

**Industry example (building a summary table for export):**
```DAX
Category Summary =
ADDCOLUMNS (
    VALUES ( Product[Category] ),
    "Total Sales", [Total Revenue],
    "Total Units", SUM ( Sales[Qty] )
)
```

## 5. The `VAR` Keyword — Writing Clean, Efficient DAX

```DAX
VAR VariableName = Expression
RETURN Expression
```

**Industry example (avoiding repeated calculation, improving readability & performance):**
```DAX
YoY Growth % =
VAR CurrentSales = [Total Revenue]
VAR PriorSales = CALCULATE ( [Total Revenue], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )
RETURN
    DIVIDE ( CurrentSales - PriorSales, PriorSales )
```
Using `VAR` is considered **best practice** in real-world DAX because:
- It avoids recalculating the same expression multiple times.
- It makes formulas easier to debug (you can test each VAR).
- It improves query performance significantly on large models.

## 6. Powerful Function Combinations (What You'll Actually See on the Job)

### 6.1 CALCULATE + FILTER + ALL → Contribution Margin / Market Share
```DAX
Market Share % =
DIVIDE (
    [Total Revenue],
    CALCULATE ( [Total Revenue], ALL ( Product ) )
)
```

### 6.2 SWITCH + TRUE + Multiple Measures → Dynamic KPI Selector
Paired with a "Field Parameter" or disconnected table + slicer:
```DAX
Selected KPI =
SWITCH (
    SELECTEDVALUE ( KPISelector[KPI] ),
    "Revenue", [Total Revenue],
    "Profit", [Total Profit],
    "Orders", [Number of Orders],
    [Total Revenue]
)
```

### 6.3 CALCULATE + SAMEPERIODLASTYEAR + DIVIDE → YoY Growth (Finance staple)
```DAX
YoY % =
DIVIDE (
    [Total Revenue] - CALCULATE ( [Total Revenue], SAMEPERIODLASTYEAR ( 'Date'[Date] ) ),
    CALCULATE ( [Total Revenue], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )
)
```

### 6.4 RANKX + ALL + CALCULATE → Leaderboard that ignores page filters
```DAX
Sales Rep Rank =
RANKX (
    ALL ( SalesRep[RepName] ),
    CALCULATE ( [Total Revenue] )
)
```

### 6.5 FILTER + SUMX → Weighted Average (common in pricing/finance)
```DAX
Weighted Avg Price =
DIVIDE (
    SUMX ( Sales, Sales[Qty] * Sales[UnitPrice] ),
    SUMX ( Sales, Sales[Qty] )
)
```

### 6.6 CALCULATE + ISFILTERED / HASONEVALUE → Guard Clauses for Dashboards
```DAX
Safe Category Sales =
IF (
    HASONEVALUE ( Product[Category] ),
    [Total Revenue],
    "Select a single category"
)
```

### 6.7 ADDCOLUMNS + SUMMARIZE + FILTER → New Customer Segmentation Table
```DAX
Customer Segments =
ADDCOLUMNS (
    SUMMARIZE ( Sales, Customer[CustomerName] ),
    "Total Spend", [Total Revenue],
    "Segment",
        SWITCH (
            TRUE(),
            [Total Revenue] > 50000, "Platinum",
            [Total Revenue] > 20000, "Gold",
            [Total Revenue] > 5000, "Silver",
            "Bronze"
        )
)
```

## 7. Common Industry Use-Case Recipes

### 7.1 Retail — Basket Analysis / Repeat Purchase Rate
```DAX
Repeat Customers =
CALCULATE (
    DISTINCTCOUNT ( Sales[CustomerID] ),
    FILTER (
        VALUES ( Sales[CustomerID] ),
        CALCULATE ( DISTINCTCOUNT ( Sales[OrderID] ) ) > 1
    )
)
```

### 7.2 Finance — Running Total / Cumulative Sales
```DAX
Cumulative Sales =
CALCULATE (
    [Total Revenue],
    FILTER (
        ALLSELECTED ( 'Date'[Date] ),
        'Date'[Date] <= MAX ( 'Date'[Date] )
    )
)
```

### 7.3 HR / Workforce — Headcount Snapshot (semi-additive measure pattern)
```DAX
Active Headcount =
CALCULATE (
    COUNTROWS ( Employee ),
    FILTER (
        Employee,
        Employee[HireDate] <= MAX ( 'Date'[Date] ) &&
        ( ISBLANK ( Employee[TerminationDate] ) || Employee[TerminationDate] > MAX ( 'Date'[Date] ) )
    )
)
```

### 7.4 Supply Chain — Inventory Days on Hand
```DAX
Days on Hand =
DIVIDE (
    [Ending Inventory Qty],
    CALCULATE ( AVERAGEX ( 'Date', [Total Units Sold] ) )
)
```

### 7.5 Marketing — Customer Acquisition Cost (CAC)
```DAX
CAC = DIVIDE ( [Total Marketing Spend], [New Customers] )
```

## 8. Best Practices Checklist (What Separates a Beginner from a Professional)

1. **Always use `DIVIDE()`** instead of `/` to avoid divide-by-zero errors.
2. **Use `VAR`** to store intermediate results — improves readability and performance.
3. **Prefer measures over calculated columns** for anything that should react to filters.
4. **Build a proper Date table** and mark it as the official date table before using any time-intelligence function.
5. **Use `SELECTEDVALUE()`** instead of `VALUES()` when expecting a single selected item — it handles the "multiple values" case gracefully.
6. **Avoid `ALL()` when `ALLSELECTED()` or `REMOVEFILTERS()`** actually fits the business need — `ALL` wipes out everything, including slicers the user has deliberately applied.
7. **Name measures clearly** (e.g., `Total Revenue`, `YoY Growth %`) — avoid vague names like `Measure1`.
8. **Comment complex DAX** using `//` so the next analyst (or future you) understands intent.
9. **Test measures in a simple table visual** before embedding them inside more complex ones.
10. **Watch for circular dependency** and performance traps — heavy row-by-row iterators (`SUMX`, `FILTER`) on large fact tables can slow reports; use them purposefully.
